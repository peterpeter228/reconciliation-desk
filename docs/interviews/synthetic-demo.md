# 合成演示脚本：不是账簿操作

状态：PREPARED；技术案例已在单元层实测，访谈演示未执行。全程使用仓库合成 CSV 和虚构公司，不接入外部系统。先让受访者讲最近案例，再演示，防止诱导问题描述。

1. 说明本地处理、不连接账户、不入账；下载不证明过账。展示 SYNTHETIC 标签。
2. 解释目标案例：收款 $10,000、实际银行 $9,100；只看到差额 $900 不足以判定手续费。让受访者先说需要什么证据。
3. 本地导入 ST、bank 和 native-style.csv。指定 clearing / bank 语义。展示原生列没有 Linked IDs，金额对上仍缺关系。只把界面实显状态读给用户，不预设“成功”。
4. 展示本地合成关系凭据如何明确指出 payment、QB transaction、deposit；不要用金额反推出 IDs。保留原件 hash、行号和补充表说明。替换为 supplemented.csv，添加合成 processor settlement。若 UI 导入阻断，记录阻断，不切换 demo 假装同流程成功。
5. 展示三条边、gross/net/fee 和缺失证据；说明该案例三条边确认不替代完整期间、科目和人工审批。故意撤一项 linkage，展示不再完整确认。
6. 演示复核摘要/工作底稿，不在任何 QBO/QBD 公司导入。若另展示 fee-only CSV，只在本地看 Dr fee / Cr clearing，强调不是 Dr bank / Cr income。所有假文档只在演示上下文使用。
7. 开放提问：“哪里对你没用？哪一步最可能拿不到证据？”最后才比较 A/B 和不用工具选项。

观察记录：受访者能否自行解释候选/确认；是否以为 Role 是原生列；是否理解补列成本；是否把下载当过账。完成时长只能现场实测，脚本不预设分钟数或节省百分比。
