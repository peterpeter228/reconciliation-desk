## 4. 独立审查重点：业务语义优先于绿色测试

对发现建立问题清单：ID、严重性、现象、影响、文件/行号、证据、复现命令、根因、修复、回归测试、剩余限制。先写能揭示真实缺陷的失败测试，再修代码；不要通过降低断言或伪造测试夹具让它变绿。

### 4.1 来源、覆盖和公式

- 原始文件字节、编码、解析文本、来源摘要、工作表、物理行号、组号与归一化行必须一致。检查伪造 normalized rows、替换原文件、跨公司/币种/期间、同名文件不同内容、缺失引用。
- 哈希只支持完整性和内容绑定，不证明文档真实、来自 QuickBooks 或 reviewer 可信。手动勾选、账户名称存在、输入了交易号，也不是来源已经证明。
- 清楚区分来源直接证明、人工判断、用户声明、推断和未知。技术无法验证真实性时如实标记，设计专业复核流程，不是假装解决。
- 单个完整 Transaction Journal 不证明整月 GL 完整；单账户 activity 可合法只有一边，但不能被当作完整 journal。不能用 clearing-only 数据证明其他账户没有已记手续费。
- XLSX 控制公式必须按狭窄允许规则保留原文、地址、缓存并独立汇总，不执行任意公式。原样本 H9/I9/H10/I10 的公式为 H7+H8、I7+I8、H9、I9；缓存 900，对应 90000 cents。检查缓存缺失/矛盾、公式变体、外链、宏、恶意 ZIP/XML、超大文件和 posting 公式。
- 完整 journal 缺失一腿时隔离整个可靠识别的经济交易，不是只删问题行后剩余部分照常入账。Partial 恢复应保留调查价值，但不能升级完整期间覆盖。

### 4.2 全量 GL、手续费和正确分录

- 不能先过滤掉“看似无关” GL 再验证。全量输入中区分当前 case、其他有证据关联的 case 和未知关联。
- OTHER_CASE 不得仅凭任意标签或一个存在的 digest 绕过阻断；检查关联是否真的足以支持排除。未解释关联保持 unknown；不能把其他期间正常手续费都误挡成当前案例重复。
- 核查“bank 已记账”与“银行 feed 出现”区别、“收费账单”与“已入 GL”区别。
- 受支持普通资产 clearing 示例：gross 10,000 已记入 clearing，net 9,100 已记银行并贷记 clearing，900 为经证实未记的费用。补充分录仅 Dr 费用 900 / Cr clearing 900，绝不能再次 Dr bank。
- 若 900 差额其实是 600 fee + 300 hold，不能全记 fee；已有 fee、部分 fee、退款/冲销、负债 clearing、UF、额外同 case posting 或事实矛盾，不可套普通模板。
- 上述阻断的是未经证明的会计导入，不是所有交付物。继续给调查工作底稿、已知/未知列表、人工处置候选和需要补充的具体证据。
- 金额使用精确整数最小单位、显式币种；检查日期/时区/区域小数格式/负数/退款/重复记录，任何近似匹配不能静默破坏守恒。

### 4.3 UF：完整正向路径和重复入账防护

- ST payment ID 不是 QuickBooks Payment ID。UF 候选可输出，但不能伪装可入账/已验证。
- 正向已复核说明至少需要真实语义的 QB payment identifiers、当前未存款状态、不属于其他 deposit、目标 bank/fee 账户存在及类型、日期、净额手续费证据和完整适用覆盖。
- 用明确标注合成的全证据 fixture 测 UI 正向说明，并测试已经 deposited、缺失 ID、重复 payment、跨公司、金额不守恒和已有费用反例。
- 区分“匹配已存在银行记录”与“Categorize/新建交易”，避免重复 deposit/收入/银行腿。UF reviewed instructions 不是已通过导入的文件。
- 每一步说明用户应在何处看什么、如何确认、何时停止，不能只输出一堆红色布尔门槛。

### 4.4 Case 身份、审批、保存、重开与恢复

- economic case ID、action ID、engine group ID、input digest 各司其职。修改映射、行顺序、重新计算或 Save/Open 不能将同一经济操作变成“全新、允许再导出”。
- 检查 merge/split、重复导入同文件、不同 filename 同内容、跨期间、跨工作区、多个标签页、旧 schema、篡改项目和孤立历史。
- 重新打开、事实/账户/金额/日期/来源改变均应撤销相关旧批准。异步结果不得覆盖新输入、已清空或卸载 case。
- 一次下载不证明入账成功；浏览器下载失败也不自动说明未曾交付。unknown 保留，提供检查实际账簿/核对下载的恢复路径，不盲目重试会计导出。
- 明确 local-first 没有跨设备全局防重保证。删除本地文件或恶意重写无法靠自带 hash 防止，不要写“绝对防篡改/绝无重复”。
- 无效文件、导入取消、超时、refresh、back/forward、重复点击、worker 取消应保留可恢复状态。对历史瞬时回到入口问题建立可观察证据和复现矩阵；未复现就记录，不宣称修复。

### 4.5 安全和隐私

检查 CSV 公式注入、导入型 XSS、路径/文件名、ZIP bomb、内存/行数预算、反序列化/schema、下载内容与实际批准的一致性、worker 竞态、依赖风险和前端错误日志泄漏。真实浏览器记录运行时网络请求，核对“文件不上传”陈述；静态检查不足以证明没有网络外发。

不要把清理后的测试日志视为客户数据可以公开的理由。采用最小必要遥测和日志，默认不记录完整财务行。确认 demo、合成 fixture、真实用户导入在 UI 和导出中不会混淆。

## 5. 产品与 UI：让用户完成任务，而非美化空壳

在现有结构上优先改善以下连续流程：

资料准备 → 上传和映射 → 验证范围/错误恢复 → 差异 case → 证据和解释 → 人工复核 → 工作底稿或受限批准输出 → 保存/重开 → 接收方复核。

先亲自走一遍，记录步数、重复输入、术语障碍、耗时和失败恢复，再决定改什么。不要默认重做首页或更换 UI 框架。

至少做到：
- 首屏一句话说清针对谁、解决什么、不做什么；入口明确区分 Demo 和自己的资料。
- 上传页显示所需来源、报表类型、期间/账户范围和可接受格式；原生 XLSX 不能被过时文案误判成全不支持。
- 错误说明“哪一行/哪笔交易、为什么、保留了什么、怎么修复”，不是 raw JSON 或泛化“失败”。
- 结果主次清楚：需立即复核、资料不全、候选匹配、已复核。颜色不独占表达，金额/方向/币种统一。
- 证据默认摘要，按需展开原始行与来源；减少重复填表，但不得自动勾选未证明事实。
- 每个阻断有唯一或少数明确下一步，仍可下载调查工作底稿。用户不必完成入账流程才得到价值。
- 展示保存状态、恢复能力、重新批准原因、过去导出/未知入账状态；敏感项目下载有简短清楚提醒。
- 统一字体层级、间距、表格密度、按钮语义和 focus；覆盖键盘、屏幕阅读器标签、缩放及窄屏。财务数据表可合理滚动，关键决策与恢复操作不能消失。
- 至少使用桌面和手机窄屏视口实际测试。手机不是要求在手机完成专业入账，而是应能阅读状态、检查证据和理解下一步。

优化收益用实际任务完成时间、点击/输入数量、错误恢复成功、可理解性来描述。不要以“高级感”取代业务验收。

## 6. 实施顺序与完成条件

### 阶段 A：基线和独立审查

恢复环境并运行原有检查。保留失败记录，区分环境缺陷、已有缺陷与新增缺陷。形成优先级排序和最小可交付里程碑。评估新增人工确认字段是否真的绑定事实，还是只把风险转嫁成 checkbox。

### 阶段 B：先解决阻断交付或错账风险

优先 P0/P1、数据恢复和身份/证据缺陷，再补 UF 正向说明、当前 case 生命周期和原生导入回归。先完成一个用户可以从头走到底的可靠范围，不同时扩张多个 unsupported 会计场景。

### 阶段 C：可用性交付

优化实际主流程、文案、可访问性和窄屏；继续保留调查/人工判断/批准输出三个层级。输出接收方可读摘要：范围、来源、差异、已知事实、未核实项、建议、需谁确认、非自动记账声明。

### 阶段 D：独立验收

跑完整回归和真实浏览器。检查实际下载字节，不只断言按钮被点击。任何会计软件导入限制明确标记，不能为了“完成”突破权限。

### 阶段 E：商业验证准备

完成下一节的证据与方案，不擅自对外执行。最终给出现在能交付什么、不能交付什么和唯一最值得继续的验证。

不是固定 18 小时上限，也不是无限优化。每阶段记录预计/实际投入和剩余价值；发现高成本低证据方向应收缩或停止。不得为了填充报告新增大批重复文档。

## 7. 从可用到可收费：验证而非承诺

首先明确一个狭窄目标用户和付款人，例如使用 ServiceTitan + QuickBooks 的服务商财务人员或服务这些企业的 bookkeeper。不要假设所有公司都有此痛点。

查当前官方产品文档、公开价格和可信实际用户问题，区分功能已经存在与尚未解决的工作。ServiceTitan、QuickBooks 已有 payment/settlement/deposit/reconciliation 功能；差异化必须证明是跨来源异常解释、历史清理、证据包或降低人工复核时间，而不是“我们也能对账”。检索不到不等于竞品没有。

准备可证伪的商业假设：
- 触发场景、现有做法、频率、谁痛、谁批准采购、谁实际使用。
- 当前替代方案为何不足，换用本工具的成本和收益。
- 最小服务范围：一家公司、一个期间、明确账户/来源/行数上限、具体交付物、排除项、返工边界。
- `$199` 单期人工辅助诊断只能作为待验证报价假设，不是已接受价格或收入证据。允许提出更合适报价，但须说明依据。
- 统计准备资料、清洗、解释、复核、支持、返工的全部人工时间，列举获客、支付、托管和退款成本假设。分别算单次贡献与可持续收益，不把营业额当利润。
